## Core Principles

### 1. Visual Design
- **Color System:** Use only the palette in [design-system/structural-engineering/MASTER.md](../design-system/structural-engineering/MASTER.md)
  - Professional Blue (#1F4788) for primary UI elements
  - Structural Green (#2E7D32) for validation/success
  - Engineering Orange (#F57C00) for warnings
  - Critical Red (#C62828) for errors
- **Typography:** Segoe UI for headings/body, Consolas for technical values
- **Spacing:** 8px grid multiples (8, 16, 24, 32, 40, 48...)
- **Components:** Follow specifications in MASTER.md exactly

### 2. Interaction Design
- **Input Validation:** Real-time validation with green checkmark (✓) for valid, red error message for invalid
- **Error Messages:** Below field, in red, 11px text, actionable and specific
- **Keyboard Shortcuts:** Standard (Ctrl+N, Ctrl+S, F5 for analysis)
- **Undo/Redo:** Required for all user-editable actions
- **Tooltips:** All technical abbreviations explained

### 3. Accessibility (WCAG 2.1 Level AA)
- **Text Contrast:** All text must have ≥ 4.5:1 contrast ratio
- **Keyboard Navigation:** Tab, Shift+Tab, Arrow keys must work
- **Focus Indicators:** Visible 2px outline when tabbing
- **Color Independence:** Don't use color alone for meaning (add icons/text)
- **Screen Readers:** Labels, aria-labels, semantic structure

### 4. Professional Workflow
- **Data Display:** Right-aligned numbers, monospace font, 4-6 decimal places
- **Units:** Always include unit labels (mm, kN, MPa, etc)
- **Validation:** Cross-field validation (section depth must be < member length)
- **Performance:** Async solver (non-blocking UI), progress indicator
- **Export:** PDF reports and Excel spreadsheets with professional formatting

### Task 1: Build a Property Editor for Beam Dimensions
**Requirements:**
- Input field for depth with unit selector
- Validation (depth must be > 0)
- Green checkmark when valid
- Red error message if invalid
- Monospace font for value display

**Template to Use:**
- Reference: [COMPONENT_QUICK_REFERENCE.md](../src/UI/Templates/COMPONENT_QUICK_REFERENCE.md) → Section 1

**Implementation:**
```xaml
<!-- Quick template from QUICK_REFERENCE -->
<Grid Margin="0,8">
    <Grid.ColumnDefinitions>
        <ColumnDefinition Width="120" />
        <ColumnDefinition Width="*" />

```

## Pre-Delivery Checklist (Always Verify)

When completing a feature, verify:

### Design & UX
- [ ] All dimensions/loads/results include units (mm, kN, MPa)
- [ ] Only palette colors used (no arbitrary hex)
- [ ] Monospace font for numerical values
- [ ] Icons from approved set (Heroicons/Material Design)
- [ ] Keyboard shortcuts documented in Help
- [ ] Undo/Redo implemented for user edits
- [ ] Context menus available (right-click)
- [ ] Tooltips explain all abbreviations

### WPF Implementation
- [ ] MVVM pattern followed (no code-behind logic)
- [ ] Resource dictionary centralizes colors/brushes
- [ ] Data binding uses INotifyPropertyChanged
- [ ] Converters format numbers (StringFormat=F4)
- [ ] No hardcoded values (use config files)
- [ ] Window layout saves/restores state

### Data & Analysis
- [ ] Input validation prevents invalid units
- [ ] Error messages are user-friendly
- [ ] Results export includes all assumptions
- [ ] Calculation logs available for verification
- [ ] PDF/Excel export uses professional template

### Accessibility (WCAG 2.1 AA)
- [ ] Text contrast: 4.5:1 minimum
- [ ] Keyboard navigation works (Tab, Shift+Tab)
- [ ] Focus indicators visible
- [ ] Abbreviations have tooltips
- [ ] Status shown by icon + text (not color only)

### Performance & Reliability
- [ ] Large models (100k+ elements) don't freeze
- [ ] Analysis runs asynchronously
- [ ] Progress indicator shown during long ops
- [ ] Memory usage monitored
- [ ] Undo/Redo stack limited

## Known Constraints & Anti-Patterns

### ✓ DO
- Use only palette colors
- Monospace for technical values
- Green/Orange/Red for status (not color alone)
- Right-align numbers in tables
- Include units in every measurement
- Validate input (cross-field validation)
- Async solver (don't block UI)
- Undo/Redo for all edits

### ✗ DON'T
- Bright neon colors or gradients
- Emoji as icons (use Heroicons)
- Decorative animations
- Missing unit labels
- Modal dialogs without Cancel option
- Color-only status indicators
- Unexplained abbreviations (always tooltip)
- Hardcoded color values in XAML
